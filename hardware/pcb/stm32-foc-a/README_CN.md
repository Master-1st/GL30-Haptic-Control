## 设计依据

继续使用已经购买的 STM32G474CET6、DRV8316RRGFR、TLV1704、TLV75533、SN74LVC1G07、TXU0202、TMUX1511；编码器沿用电机自带 AS5048A 板。没有为了使用开源整板更换已购主芯片。

## 已核对的关键连接

- PB9 控制 `MOTOR_PWR_EN`，不再用于调试翻转或灯环；PA12 控制 `nSLEEP`，两者复位默认低。
- PC13 推挽、低速，只驱动 U7 的逻辑输入；PC13 低表示未就绪/故障。U7 输出属于 `3V3_ESP` 域，该电源不与 STM32 的 3.3 V 并联。
- PA3 为开漏 DRVOFF、外部上拉；PB12 为低有效 BKIN。禁止自动恢复输出，保持故障锁存。
- 母线 ADC 分压为 100k＋100k / 20k，倍率 **11**；过压比较器的 100k / 20k 是另一支路。
- U2 裸露焊盘 **41 接地**；OUTA 13/14、OUTB 16/17、OUTC 19/20 各属于同一相。充电泵 1 µF 电容接 CP 与 VM，不能接错到地。
- NTC 为外接绝缘探头，10k@25 ℃、B3950、10k 上拉；固件在 200 Hz 监测任务换算温度，ADC 中断只记录原始值。
- J3 号序是 A 板焊盘号，厂家六线颜色为黑地、红 5 V、绿 MISO、黄 MOSI、蓝 CLK、白 CSn；不能当成厂家连接器的几何顺序。

J1/J2/J3 是拟采用的直接焊线接口，图上“不装配”标记表示不焊连接器器件，**不表示删除 PCB 焊盘**。JP1 常开，C53/C54 为不装的容量预留。

## 验证结果与边界

- KiCad 10.0.6 正式解析、导出 9 页 PDF 和 XML 网表。
- ERC：**0 个错误、0 个警告**，未添加 ERC 排除项。工具默认忽略的规则在原始 ERC JSON 中保留。
- 独立读取 KiCad 导出的网表，与输入逐端点比对：**212 个板上对象、518 个连接端点、9 个明确不连接引脚、101 个命名网络**全部一致。
- 212 个对象包括 146 个器件/焊盘接口及 66 个测试点，包含 DNP；不是需要采购 212 个芯片。
- 已赋封装的 202 个对象通过“符号物理脚号存在于封装焊盘”检查。该检查不能证明封装方向、焊盘尺寸和装配可制造性。
- PDF 9 页已逐页查看，修正了标签对齐、器件字段重叠与页面边界问题。

ERC 不验证保护阈值精度、模拟瞬态、热设计、驱动开关时序、机械配合或上电行为。原理图里的约 ±1.795 A、约 16.006 V 为名义计算，尚非实测限值。

## 布局前仍需确认

| 项目 | 当前状态 / 后续动作 |
| --- | --- |
| U2 精确封装 | 已确认 RGF0040E、40 外围脚＋41 号 EP；需依 TI 推荐焊盘绘制并复核，未套用相近的 6×6 QFN40 |
| C28/C29/C53/C54 | Panasonic 35SVPF39M，需复核 E7 外形、极性与可用库封装 |
| SW1 | ALPS SKRPASE010，四焊盘及内部并联对已明确，待选/核对实物封装 |
| J1/J2/J3/J4 | 线径、焊线孔/应力释放，以及实际 SWD 座键位待明确；这四项与前述器件合计 10 个位号未赋封装 |
| J5/J6 | 已选 FH12-10S-0.5SH，下接触；两端针 1、排线同面/异面仍需实物核对 |
| AS5048A 原厂小板 | 型号和六线接口已知；必须确认 5 V 模式所需的本地 VDD3V→GND 10 µF。A 板电缆口电容不能替代此项 |
| 故障/掉电行为 | `HARD_FAULT_N` 高不等于母线健康；还需母线、驱动配置读回、有效采样及编码器等启动条件。当前产品固件保持母线使能和 nSLEEP 低、禁止 arm |
| U9 掉电输入 | TMUX1511 掉电时信号需在允许范围内；VM 分压后再接入。实际再生/线束瞬态需测量 |
| 灯环与普通按键 | GPIO/扩展器、供电域和 C 板接口尚未最终定案；未把候选方案写成已购事实 |

MOTOR_BUS 的限流、防反接、回生钳位属于 B 板/供电系统；A 板 TVS 和局部电容不替代制动电路。B/C 板尚未包含在这份 A 板原理图中。

## 文件再生成与来源

编辑时直接使用 KiCad。`generate_schematic.py` 是首版生成工具，会重写本目录原理图，**人工编辑后不要直接重跑覆盖**。需要复现时先复制工程，在副本运行：

```powershell
python -X utf8 generate_schematic.py --runtime '<KiCad 安装目录>'
kicad-cli sch export netlist --format kicadxml -o GL30_A.net.xml GL30_A_STM32_FOC.kicad_sch
kicad-cli sch erc --format json --severity-all --exit-code-violations -o erc.json GL30_A_STM32_FOC.kicad_sch
python -X utf8 verify_export.py --netlist GL30_A.net.xml --erc erc.json --output acceptance.json
```

符号/封装出处与授权见 [THIRD_PARTY.md](THIRD_PARTY.md)。芯片的官方手册链接写入器件 Datasheet 字段。原始来源路径与 SHA-256 见 `generation_manifest.json` 及交付验证文件。
